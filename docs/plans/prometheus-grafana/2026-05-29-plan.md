# 1. Context

**Problem:**
HMS-PRO hiện không có khả năng quan sát (observability) theo thời gian thực. Khi một microservice gặp sự cố (CPU tăng, memory leak, Kafka consumer lag, DB pool cạn), không có công cụ để phát hiện và phản ứng kịp thời. Tính năng này bổ sung Prometheus + Grafana để giải quyết vấn đề này mà không ảnh hưởng đến logic nghiệp vụ hiện tại.

**Affected Modules:**
- `GatewayMS` (port 9000) — expose `/q/metrics`
- `UserMS` (port 8080) — expose `/q/metrics` + DB connection pool metrics
- `ProfileMS` (port 9100) — expose `/q/metrics` + DB + Redis metrics
- `Appointment` (port 9200) — expose `/q/metrics` + DB + Kafka producer metrics
- `PharmacyMS` (port 9300) — expose `/q/metrics` + DB metrics
- `PaymentMS` (port 8086) — expose `/q/metrics` + DB + Kafka producer metrics
- `NotificationMS` (port 8085) — expose `/q/metrics` + Kafka consumer metrics
- `docker-compose.yml` — thêm Prometheus + Grafana services
- `k8s/` — thêm monitoring manifests

**Non-Goals:**
- Không cấu hình Alertmanager (để sau)
- Không tích hợp Slack/PagerDuty alerts
- Không thêm distributed tracing (Jaeger/Zipkin)
- Không monitor frontend hms-fe
- Không cấu hình Prometheus Operator / ServiceMonitor CRD

# 2. Constraints

**Language:** `Java 21`
**Framework:** `Quarkus 3.15.1`
**Architecture:** `Microservices — Pull-based metrics scraping`
**Build Tool:** `Maven`

**Rules:**
- Không modify logic nghiệp vụ (Resource, Service, Repository classes)
- Chỉ thêm dependency vào `pom.xml`, không tạo file Java mới trong services
- Grafana dùng port `3001` (tránh conflict với hms-fe port `3000`)
- Prometheus dùng port `9090`
- Metrics endpoint KHÔNG được route qua GatewayMS/Ingress ra internet
- `quarkus.management.enabled` phải được xem xét per-service để tránh conflict

**Performance Budgets:**
- Overhead metrics collection: < 5MB thêm memory per service
- Scrape interval: 15s (không scrape quá nhanh gây tải)

# 3. Conventions

**File Naming:**
- Config files: `kebab-case.yml` (ví dụ: `prometheus.yml`, `grafana-deployment.yaml`)
- K8s manifest: `<service-name>-<type>.yaml` (ví dụ: `prometheus-deployment.yaml`)
- Dashboard JSON: `<topic>-dashboard.json`
- Thư mục monitoring: `monitoring/prometheus/`, `monitoring/grafana/`

**Quarkus Management Port:**
Quarkus có hai chế độ expose metrics:
1. **Cùng HTTP port** (mặc định khi `quarkus.management.enabled=false`): `/q/metrics` trên port chính của service
2. **Management port riêng** (khi `quarkus.management.enabled=true`): `/q/metrics` trên port 9000 (mặc định)

→ **Quyết định**: Dùng chế độ 1 (cùng HTTP port, KHÔNG bật management port riêng) để đơn giản hóa cấu hình. Prometheus sẽ scrape `<service-host>:<service-port>/q/metrics`.

**Lý do**: GatewayMS đang dùng port 9000 rồi. Nếu bật `quarkus.management.enabled=true` mà không chỉ định port riêng cho từng service sẽ bị conflict.

**K8s Labels cần thiết cho Prometheus scraping:**
```yaml
annotations:
  prometheus.io/scrape: "true"
  prometheus.io/path: "/q/metrics"
  prometheus.io/port: "<service-port>"
```

# 4. Contracts

## 4.1 Metrics Endpoint Contract

```
GET /<service-host>:<port>/q/metrics
  - pre:  quarkus-micrometer-registry-prometheus dependency tồn tại trong pom.xml
  - post: trả về text/plain với Prometheus exposition format
  - format: # HELP <metric_name> <description>\n# TYPE <metric_name> <type>\n<metric_name>{labels} <value>
  - auth:  KHÔNG yêu cầu authentication (internal-only endpoint)
  - throws: 404 nếu dependency chưa được thêm
```

## 4.2 Prometheus Scrape Config Contract

```yaml
# prometheus.yml structure
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: '<service-name>'
    static_configs:
      - targets: ['<host>:<port>']
    metrics_path: '/q/metrics'
```

## 4.3 Grafana Datasource Provisioning Contract

```yaml
# datasources/prometheus.yml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    url: http://prometheus:9090  # Docker Compose internal DNS
    isDefault: true
    access: proxy
```

## 4.4 Grafana Dashboard Provisioning Contract

```yaml
# dashboards/dashboard.yml
apiVersion: 1
providers:
  - name: 'HMS-PRO Dashboards'
    type: file
    options:
      path: /etc/grafana/dashboards
```

## 4.5 Docker Compose Service Contract

```yaml
prometheus:
  image: prom/prometheus:v2.47.0
  ports: ["9090:9090"]
  volumes:
    - ./monitoring/prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
  
grafana:
  image: grafana/grafana:10.1.0
  ports: ["3001:3000"]  # external:internal
  volumes:
    - ./monitoring/grafana/provisioning:/etc/grafana/provisioning
    - ./monitoring/grafana/dashboards:/etc/grafana/dashboards
  environment:
    - GF_SECURITY_ADMIN_PASSWORD=admin
```

## 4.6 K8s Deployment Contract

```yaml
# prometheus-deployment.yaml
containers:
  - name: prometheus
    image: prom/prometheus:v2.47.0
    ports: [{containerPort: 9090}]
    volumeMounts:
      - name: config
        mountPath: /etc/prometheus/prometheus.yml
        subPath: prometheus.yml
volumes:
  - name: config
    configMap:
      name: prometheus-config
```

# 5. Target Architecture

**Components:**
- `quarkus-micrometer-registry-prometheus` — Quarkus extension tự động expose `/q/metrics` trên mỗi service
- `monitoring/prometheus/prometheus.yml` — Cấu hình scrape targets cho tất cả services
- `monitoring/grafana/provisioning/` — Auto-provision datasource và dashboards khi Grafana khởi động
- `docker-compose.yml` — Orchestrate Prometheus + Grafana trong local dev
- `k8s/monitoring/` — K8s manifests cho production monitoring

**Interaction Flow:**

```
┌─────────────────────────────────────────────────────────────────┐
│ Quarkus Services (mỗi 15s được scrape)                         │
│                                                                  │
│  GatewayMS:9000/q/metrics                                       │
│  UserMS:8080/q/metrics                                          │
│  ProfileMS:9100/q/metrics  ◄──── scrape (HTTP GET) ────┐       │
│  Appointment:9200/q/metrics                             │       │
│  PharmacyMS:9300/q/metrics                             │       │
│  PaymentMS:8086/q/metrics                              │       │
│  NotificationMS:8085/q/metrics                         │       │
└─────────────────────────────────────────────────────────┘       │
                                                          │        │
                                             ┌────────────┴──────┐ │
                                             │ Prometheus :9090  │─┘
                                             │ (TSDB storage)    │
                                             └────────┬──────────┘
                                                      │ PromQL query
                                             ┌────────▼──────────┐
                                             │  Grafana :3001    │
                                             │  (Dashboards)     │
                                             └───────────────────┘
                                                      ▲
                                             Developer Browser
```

**Key Decisions:**
1. **Pull model** (không phải Push): Prometheus chủ động gọi vào services, đơn giản hơn, không cần services biết về Prometheus
2. **Management port OFF**: Tất cả services expose `/q/metrics` trên HTTP port chính để tránh conflict port 9000 với GatewayMS
3. **Provisioning-as-code**: Grafana datasource + dashboards được cấu hình bằng file YAML (không setup thủ công qua UI), đảm bảo reproducible deployment
4. **Versioned images**: Dùng versions cụ thể (`v2.47.0`, `10.1.0`) thay vì `latest` để tránh breaking changes

- Dashboards phải có `${service}` variable để filter theo từng microservice

**Key PromQL queries cho dashboards:**

*JVM Dashboard:*
```promql
# Heap memory usage
jvm_memory_used_bytes{area="heap", service="$service"}
# GC pause time
rate(jvm_gc_pause_seconds_sum{service="$service"}[5m])
# CPU usage
process_cpu_usage{service="$service"}
```

*HTTP Dashboard:*
```promql
# Request rate
rate(http_server_requests_seconds_count{service="$service"}[5m])
# P95 latency
histogram_quantile(0.95, rate(http_server_requests_seconds_bucket{service="$service"}[5m]))
# Error rate
rate(http_server_requests_seconds_count{status=~"5..",service="$service"}[5m])
```

*Kafka Dashboard:*
```promql
# Consumer lag
kafka_consumer_records_lag{service="$service"}
```

**Acceptance Criteria:**
- [ ] `monitoring/grafana/provisioning/datasources/prometheus.yml` hợp lệ
