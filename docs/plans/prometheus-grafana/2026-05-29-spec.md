# Spec: Prometheus + Grafana Monitoring for HMS-PRO

## 1. Problem Statement

Hệ thống HMS-PRO hiện tại không có khả năng quan sát trạng thái vận hành (observability) theo thời gian thực. Khi một microservice gặp sự cố (CPU tăng cao, memory leak, Kafka consumer bị lag, DB connection pool cạn kiệt), đội vận hành không có công cụ để phát hiện và phản ứng kịp thời. Tính năng này bổ sung một lớp monitoring đầy đủ sử dụng **Prometheus** (thu thập metrics) và **Grafana** (hiển thị dashboard) để giải quyết vấn đề này.

## 2. Goals

- [x] Expose metrics endpoint `/q/metrics` trên TẤT CẢ 7 microservices backend (Quarkus).
- [x] Triển khai Prometheus để scrape metrics từ tất cả services định kỳ.
- [x] Triển khai Grafana với pre-built dashboards (JVM, HTTP, Kafka, DB).
- [x] Hỗ trợ cả môi trường **Docker Compose** (local dev) và **Kubernetes** (production).
- [x] Không làm ảnh hưởng đến logic nghiệp vụ hiện tại của bất kỳ service nào.

## 3. Non-Goals

- [ ] Không tích hợp với dịch vụ alert bên ngoài (PagerDuty, Slack) — có thể mở rộng sau.
- [ ] Không thêm distributed tracing (Jaeger/Zipkin) — feature riêng.
- [ ] Không cấu hình Alertmanager — để sau.
- [ ] Không monitor Frontend (hms-fe) — chỉ tập trung Backend.

## 5. Technology Decisions

### 5.1 Quarkus Extension — `quarkus-micrometer-registry-prometheus`

Quarkus tích hợp Micrometer (chuẩn đo lường phổ biến nhất cho JVM). Chỉ cần thêm một dependency vào `pom.xml` của mỗi service là endpoint `/q/metrics` sẽ tự động được tạo ra với đầy đủ metrics JVM, HTTP, và các custom metrics.

```xml
<dependency>
    <groupId>io.quarkus</groupId>
    <artifactId>quarkus-micrometer-registry-prometheus</artifactId>
</dependency>
```

**Tại sao Micrometer?**
- Được tích hợp sẵn vào Quarkus BOM (không cần version management).
- Tự động thu thập: JVM heap/GC, HTTP request count/latency/error rate, thread pool stats.
- Quarkus Kafka extension tự động expose Kafka consumer lag metrics khi có Micrometer.
- Quarkus Hibernate tự động expose DB connection pool metrics (khi dùng Agroal datasource).

### 5.2 Prometheus Configuration

Pull model: Prometheus định kỳ gọi GET `/q/metrics` của từng service để lấy dữ liệu. Cấu hình scrape targets trong `prometheus.yml`.

- **Scrape interval**: 15s (cân bằng giữa độ chính xác và tải hệ thống).
- **Retention**: 15d (mặc định, phù hợp cho dev/staging).

### 5.3 Grafana

- **Version**: Grafana 10.x (stable).
- **Datasource**: Prometheus (tự động provisioning via config file).
- **Port**: 3001 (tránh conflict với frontend hms-fe đang dùng 3000).
- **Dashboards pre-built**:
  - JVM Overview (Micrometer dashboard ID: 4701) — import từ grafana.com.
  - HTTP Service Metrics (per service — custom).
  - Kafka Consumer Lag.
  - Database Connection Pool.

### 5.4 Kubernetes Setup

Sử dụng thêm các manifest K8s:
- `k8s/monitoring/prometheus-deployment.yaml`
- `k8s/monitoring/grafana-deployment.yaml`
- `k8s/monitoring/prometheus-configmap.yaml`
- `k8s/services/prometheus-svc.yaml` / `grafana-svc.yaml`
- Cập nhật `kustomization.yaml` để include folder `monitoring/`.
- **ServiceMonitor** (tùy chọn nếu dùng Prometheus Operator) — không bắt buộc ở đây, dùng static config.

## 6. Metrics Categories

### 6.1 JVM Metrics (Tự động — tất cả services)
| Metric | Mô tả |
|--------|-------|
| `jvm_memory_used_bytes` | Heap/non-heap memory usage |
| `jvm_gc_pause_seconds` | GC pause duration |
| `jvm_threads_live_threads` | Thread count |
| `process_cpu_usage` | CPU usage của JVM process |

### 6.2 HTTP Metrics (Tự động — tất cả services)
| Metric | Mô tả |
|--------|-------|
| `http_server_requests_seconds_count` | Tổng số requests |
| `http_server_requests_seconds_sum` | Tổng thời gian xử lý |
| `http_server_requests_seconds_max` | Thời gian xử lý lớn nhất |

### 6.3 Kafka Metrics (Tự động — NotificationMS, Appointment)
| Metric | Mô tả |
|--------|-------|
| `kafka_consumer_records_lag` | Consumer lag per partition |
| `kafka_consumer_fetch_latency_avg` | Fetch latency |

### 6.4 Database Metrics (Tự động — services dùng Agroal/JDBC)
| Metric | Mô tả |
|--------|-------|
| `agroal_active_count` | Active DB connections |
| `agroal_available_count` | Available connections in pool |
| `agroal_awaiting_count` | Requests waiting for connection |

## 9. Security Considerations

- Metrics endpoint `/q/metrics` chỉ nên accessible từ Prometheus server (internal network), không expose ra ngoài Internet qua GatewayMS/Ingress.
- Grafana access: bảo vệ bằng login (admin/password trong K8s Secret).
- Trong K8s: sử dụng NetworkPolicy để giới hạn Prometheus chỉ được gọi vào `/q/metrics` của các service pods.

## 10. Constraints & Risks

| Rủi ro | Mức độ | Biện pháp giảm thiểu |
|--------|--------|---------------------|
| Port 3000 conflict với hms-fe local | Thấp | Grafana dùng port 3001 |
| Tăng nhẹ memory footprint Quarkus | Thấp | Micrometer overhead < 5MB |
| Service ports không thống nhất | Trung bình | Cần verify ports của tất cả services trong application.properties |
| K8s pod không có label service_name | Trung bình | Thêm label vào scrape config |
